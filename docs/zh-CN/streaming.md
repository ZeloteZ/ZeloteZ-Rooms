# 语音、直播和观影派对

[文档目录](README.md) · [English](../streaming.md) · [Deutsch](../de/streaming.md)

使用普通直播频道需要账户和房间成员身份。能否分享还取决于房间及频道的直播规则。详见[角色与权限](user-guide.md#角色与权限)。

## 选择媒体方式

| 方式 | 适合用途 | 工作方式 |
| --- | --- | --- |
| 语音聊天 | 浏览 Rooms 时交谈 | 先加入收听，发言时另行启用麦克风。 |
| 屏幕直播 | 分享屏幕、窗口、标签页或桌面区域 | 浏览器或桌面客户端把实时媒体发送给直播服务器。 |
| YouTube 观影派对 | 共同观看已有 YouTube 视频 | YouTube 为每位观看者提供嵌入式播放器，Rooms 同步控制。 |
| 本地视频观影派对 | 共同观看 MP4 或 WebM | Rooms 临时上传原视频，并提供给有权限的观看者。 |

语音和实时媒体在传输途中加密，由 MediaMTX 转发，并非参与者之间的端到端加密。聊天使用单独的加密模型。详见[安全与隐私](security.md)。

## 加入语音聊天

1. 打开直播频道，选择“加入语音聊天”。
2. 最初只收听。需要发言时启用麦克风，并批准浏览器或系统权限请求。
3. 浏览其他页面时，仍可用顶部语音控制静音、切换状态或返回频道。
4. 结束后退出语音聊天。

拒绝麦克风权限不一定妨碍收听。没有声音或反复重连时，请检查浏览器权限和实例媒体端口的可达性。详见[故障排查](troubleshooting.md)。

## 从浏览器分享

1. 打开允许你分享的直播频道，选择“分享屏幕”。
2. 在浏览器或系统选择器中选定屏幕、应用窗口或浏览器标签页。
3. 如果提供受支持的音频选项，可按需启用。音频来源取决于浏览器、操作系统和所选画面来源。
4. 确认分享。在直播频道中查看预览、观众、聊天和发送统计。
5. 通过 Rooms 停止按钮或浏览器共享控制结束直播。

直播期间保持来源窗口/标签页和客户端打开。浏览器缺少所需画面捕获或编解码器支持时，此方式不可用。浏览器共享请通过 HTTPS 打开实例。

每个账户同一时间只能预留或发布一个直播。实例最多允许**八个同时进行的直播**。遗留预留或断开的连接可能短暂占用名额，直到清理完成。

## 从桌面客户端分享

桌面捕获对话框将来源、裁剪、质量和音频放在同一流程中。选择屏幕、窗口或区域，批准系统权限，必要时在预览中框选区域，然后开始。

Linux 原生捕获助手提供以下预设：

| 输出 | 30 FPS 视频目标 | 60 FPS 视频目标 |
| --- | --- | --- |
| 720p | 3 Mbit/s | 4.5 Mbit/s |
| 1080p | 5 Mbit/s | 7.5 Mbit/s |
| 1440p | 8 Mbit/s | 11 Mbit/s |

这是编码器目标，不保证测得码率始终相同；还需预留音频与协议开销的上传能力。Linux 原生发布器使用 CPU x264 编码，较高分辨率和帧率需要更多处理及网络资源。

“Standard”是默认引擎。“Rooms Capture”是在后端可用时提供的实验性替代方案。可用性取决于操作系统及其捕获支持，并不保证性能优于 Standard。请在自己的硬件上验证，遇到问题时改回 Standard。

安装、平台音频选项和原生依赖详见[桌面指南](desktop.md)。

## 观看直播

在直播频道中选择正在进行的直播。“直接”使用 WebRTC，延迟较低。“缓冲”使用 HLS，会增加延迟，在直接连接不稳定时可能有用。两者仍要求直播服务器配置正确。

浏览 Rooms 时仍可使用播放和音量控制。可使用迷你/浮动播放器及侧栏控件调整布局。音量只影响自己，不会改变其他人的音量。

## 发起观影派对

选择“分享视频”，输入 YouTube 链接，或选择 **256 MiB** 以内的 MP4/WebM 文件。仅凭扩展名不能保证兼容：服务器会验证上传，观看者浏览器也必须支持文件中的编解码器。

有分享权限的成员可以添加或移除队列项目，最多保留 **16 个待播项目**。播放、暂停和跳转位置会同步；音量独立。上传使用 4 MiB 分块，管理员必须允许这些请求通过反向代理。

浏览其他页面时，视频会进入迷你播放器。最后一名观看者关闭或隐藏播放器后，YouTube 会暂停。YouTube 自身的地区、可用性和嵌入限制仍然适用。

上传的视频是临时原文件，不是加密聊天附件。派对和队列状态在内存中，不会跨服务器重启保留；文件会在启动和过期清理时移除。观影派对不是视频存档。

## 发起临时房间

在房间总览选择屏幕、YouTube 或本地文件，并选择临时房间而非持久直播频道。分享前检查访问范围：

- “向成员显示在正在直播列表”决定已登录成员能否发现房间。
- “访客访问”创建受密码保护的访客链接。
- 主持人可在“直播访问设置”中修改访问范围、撤销链接或替换密码。

访客链接在 URL 片段中包含秘密。任何持有完整有效链接的人都能访问该房间，因此只应发给预期观众。访客可以观看、使用临时直播聊天，以及播放、暂停和跳转观影视频。访客链接不创建账户，也不开放实例其他区域。

每人最多拥有一个临时房间，每个实例最多 **24 个**。未使用的草稿在**五分钟**后失效；已使用房间最长持续 **12 小时**，还要求主持人会话保持有效。主持人可以更早结束房间。

临时聊天不同于持久频道历史。服务器在房间结束前仅在内存中保留最近 **64 条加密消息**。新浏览器从加入后开始接收；持有相同有效访问和本地密钥的回访浏览器，可重新打开近期收到的消息，也包括离开期间发送的消息。详见[保留与隐私](security.md)。

## 理解统计数据

在个人资料中开启“视频接收统计”，可查看本地观看时长、接收分辨率、实测 FPS、传入码率、丢包、抖动、丢帧和编解码器（以可取得的数据为准）。该设置默认关闭，修改后立即作用于已打开的播放器。屏幕直播会显示发送统计。

- WebRTC 数据描述当前发送或接收连接。
- HLS 码率统计下载的媒体字节，缓冲加载可能使速率波动。
- 发送方网络数据描述从发送者到直播服务器的连接，不代表所有观众。
- 原生 RTMP 和 HLS 无法提供所有 RTP 丢包/抖动数据；不支持的值显示横线。
- 嵌入的 YouTube 播放器不提供 Rooms 接收统计。

这些计数器用于诊断一段连接，不能证明所有观众看到相同质量。请结合[故障排查](troubleshooting.md)、CPU 和网络负载判断。
