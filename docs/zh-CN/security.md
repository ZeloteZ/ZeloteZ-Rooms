# 安全与隐私

[English](../security.md) · [Deutsch](../de/security.md) · [简体中文](security.md) · [文档](README.md)

Rooms 对不同类型的数据采用不同的保护方式。本文介绍当前实现及其信任边界，不代表独立的密码学审计或实际部署审计。

## 数据保护概览

| 数据 | 保护方式与可见范围 |
| --- | --- |
| 普通房间、直播频道和私聊中的文字、链接、附件名称及内容、表情回应和管理理由 | 在客户端加密。服务器保存密文和分别加密的消息密钥。 |
| 房间和频道名称、成员关系、发送者、时间戳、文件大小、提及对象和回应者身份 | 服务器可读取，用于访问控制、消息投递和通知。内容加密不会隐藏这些元数据。 |
| 头像和房间图片 | 上传后由服务器处理，不是端到端加密。 |
| 语音和直播视频 | 在受支持的传输路径上加密，经 MediaMTX 转发。相对于媒体服务器而言，不是端到端加密。 |
| 上传的观影派对视频 | 临时以原始形式存储，向有权观看的用户提供，不采用聊天附件的加密方式。 |
| YouTube 观影派对 | 嵌入播放器和视频由 YouTube 直接提供给观看者，遵循 YouTube 自己的数据处理规则。 |
| 临时房间聊天 | 为每个浏览器分别加密；服务器在房间关闭前，仅在内存中保留最近 64 条密文。这与持久化的频道聊天记录不同。 |

谁可以加入和观看各种内容，由[用户指南](user-guide.md)和[直播指南](streaming.md)中的访问设置决定。

## 账户密钥与消息

官方客户端从密码派生出相互分离的登录凭据和身份解锁材料。派生过程与用户名及实例的 origin 绑定。应在创建账户之前确定最终的 `PUBLIC_ORIGIN`；更改地址不是对现有账户透明的普通迁移。

每个账户都有公钥和受密码保护的私有身份。消息密钥会分别为有权接收的人加密；私聊包含发送者和接收者。当新成员加入房间时，持有历史密钥的已解锁浏览器可以自动分享这些密钥的加密副本。

因此：

- 如果持有旧密钥的浏览器全部离线或锁定，历史记录可能要等其中一个浏览器重新上线并解锁后才能读取。
- 移除访问权限不会删除原接收者已经收到或复制的消息与密钥。
- 访问历史记录会用到长期账户密钥。不要假设系统具有前向保密，也不要假设设备或密钥泄露后旧消息仍自动受到保护。
- 登录、解锁聊天和恢复账户是相关但不同的操作。

## 实例本身是信任边界

浏览器从实例获取应用代码、公钥、成员列表和历史密钥分享信息。浏览器会在本地保存首次观察到的公钥指纹，但首次接触仍依赖实例提供的信息。

恶意或遭到入侵的实例可能修改下发的客户端代码，或错误描述接收者的成员身份和公钥。被操纵的历史分享流程可能使客户端将密钥分享给无权访问的人。这里的端到端加密并不消除对运营者和实际运行代码的信任要求。

远程实例应使用 HTTPS。HTTP 只允许用于本机回环地址。连接之前，请检查桌面应用和扩展中的实例地址。

## 身份验证与恢复

官方客户端要求新密码至少 15 个字符，并使用本地常见密码列表进行检查。服务器接收派生凭据并检查格式，因此这些强度检查并不是服务器针对任意客户端强制实施的密码策略。

所有者必须设置基于时间的身份验证器。其他成员可以自行启用 MFA 和一次性恢复码。服务器会话采用随机令牌并有到期时间；Cookie 使用 HTTP-only 和 SameSite Strict，在 HTTPS 下还使用 Secure 和 host 前缀。

MFA 密钥、账户元数据、身份验证记录和活动会话都是敏感的服务器数据。聊天采用加密存储，不代表数据库备份可以公开发布。

控制台可以恢复所有者访问权限和更换其身份验证器，但不能解密由已遗忘聊天密码保护的身份。恢复登录后，旧聊天仍可能保持锁定。具体步骤和影响见[管理指南](administration.md)。

## 本地存储与设备

浏览器可能在 session storage 中缓存聊天解锁材料，并在 local storage 中保存已观察到的公钥指纹。临时聊天使用浏览器本地设备密钥，通常保存在 IndexedDB 中；丢失这些数据可能导致旧访客消息无法读取。这些临时密钥具有有限的有效期。

桌面应用的保持登录选项使用操作系统的凭据存储保护会话和聊天解锁材料。Linux 实现会拒绝 Chromium 使用固定密钥的后备存储。系统密钥环不可用或锁定时，可能无法保持登录，但仍可手动登录。

在共用设备上应锁定操作系统会话。退出登录和关闭保持登录会影响本地访问，但其他接收者仍可能持有已收到内容的副本。

## 媒体与访客链接

MediaMTX 接收并转发语音和直播，FFmpeg 可能调整音频格式。本机回环测试可以使用未加密的 HTTP/RTMP；远程访问应采用文档中的 HTTPS/RTMPS 配置。随项目提供的配置关闭了录制，但运营者或接收者仍可能通过其他方式录制内容。

临时房间的访客链接在 URL 片段中携带密钥，并用它换取房间专属会话。只应向预期的访客分享完整链接。访客可以聊天并控制共享的观影播放。主持人可通过直播访问设置撤销或更换访客访问。撤销权限不能收回已经收到的内容副本。

普通成员房间与临时访客链接是不同的访问机制。对成员可见的房间不等于匿名公开房间。

## 部署隔离的边界

推荐镜像使用非特权用户运行，并通过 Landlock 限制组件的文件系统访问。提供的 Compose 配置默认采用只读文件系统、移除 capabilities、资源限制和回环端口绑定。这些措施减少暴露面，但运营者仍须正确配置 HTTPS、可信代理、媒体连通性、备份和主机安全。

内部媒体管理与认证端点应保持私有。只信任会替换传入请求头的可信代理所转发的客户端地址。参阅[部署](self-hosting.md)、[配置](configuration.md)和[运行维护](operations.md)。

## 报告安全问题

不要在公开 issue 中发布凭据、邀请或恢复链接、聊天内容，或尚未修复漏洞的利用细节。如果 GitHub 为该仓库提供私密漏洞报告功能，请使用该功能；否则先请[项目所有者](https://github.com/ZeloteZ)建立私密报告渠道，不要公开敏感细节。

普通缺陷报告应使用[故障排查](troubleshooting.md)中的脱敏信息清单。
