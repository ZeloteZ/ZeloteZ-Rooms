## 应使用哪种配置？

本参考适用于 `deploy/compose.image.yaml` 中推荐的单容器部署。Shell 或 `.env` 中的变量只有被该 Compose 文件用于插值或显式传给容器时才生效；仅在 `.env` 添加任意变量不会自动注入容器。

所有示例均在仓库根目录执行，并显式指定环境文件：

```sh
docker compose --project-directory . --env-file .env -f deploy/compose.image.yaml config
```

解析后的配置可能包含私有设置，不要原样粘贴到公开问题报告。Shell 导出的变量可能覆盖 `.env` 中的值；修改已有实例前，应先检查最终配置。

## 单镜像变量

以下默认值来自随附的镜像 Compose 文件和入口程序，而非 `.env.example`。

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `ROOMS_IMAGE` | `ghcr.io/zelotez/zelotez-rooms:latest` | 容器镜像。使用所需的公开软件包标签或不可变摘要。 |
| `PUBLIC_ORIGIN` | `http://127.0.0.1:${WEB_PORT:-8080}` | 规范浏览器源地址。非回环地址必须使用 HTTPS，不允许子路径、查询参数、片段或嵌入凭据。 |
| `WEB_PORT` | `8080` | 宿主机 Web TCP 端口，此 Compose 始终绑定 `127.0.0.1`；容器端口仍为 8080。 |
| `TRUST_PROXY_IP` | `0` | 仅值 `1` 启用可信代理的 `X-Real-IP` 处理，只能与会覆盖该头的外层代理配合使用。 |
| `ROOMS_TRUSTED_PROXY_IPS` | 空 | 启用代理信任时，填写准确的 IPv4/IPv6 对端地址，以逗号分隔。为空时使用回环及检测到的 Docker 网桥网关，不接受主机名或 CIDR。 |
| `VOICE_ICE_HOST` | 空 | 向客户端公布的媒体主机/IP。为空时采用 `PUBLIC_ORIGIN` 的主机名，必须能被媒体客户端直接访问。 |
| `VOICE_ICE_IP` | `127.0.0.1` | UDP 和 TCP WebRTC 媒体的宿主机绑定地址，公开 IPv4 实例通常为 `0.0.0.0`。 |
| `VOICE_ICE_PORT` | `8189` | 宿主机和容器的 UDP/TCP WebRTC 媒体端口，范围 1–65535。修改后同时改变端口映射和 MediaMTX 监听端口。 |
| `INGEST_IP` | `127.0.0.1` | RTMPS TCP 推流的宿主机绑定地址。 |
| `INGEST_PORT` | `1936` | 转发到容器 1936 的宿主机 RTMPS TCP 端口，所选端口也应写入 `STREAM_INGEST_BASE`。 |
| `STREAM_INGEST_BASE` | 空 | 公布的推流基地址，不含路径。HTTPS 实例使用 `rtmps://host:port`；本机 HTTP 测试可使用回环 RTMP。为空时 API 推导默认地址，但实际能否推流仍取决于 TLS 和入口程序模式。 |
| `RTMPS_CERT_DIR` | `./deploy/tls` | 只读挂载到 `/tls` 的宿主机目录，相对项目目录解析。RTMPS 需要 `fullchain.pem` 和 `privkey.pem`。 |
| `ROOMS_DATA_VOLUME` | `rooms-data` | 挂载到 `/data` 的准确 Docker 卷名称，修改该值不会迁移已有数据。 |
| `ROOMS_WATCH_VOLUME` | `rooms-watch-media` | 挂载到 `/watch-data` 的准确 Docker 卷名称。 |
| `ROOMS_CPUS` | `4.0` | 容器 CPU 上限，其他资源上限需通过 Compose 覆盖配置修改。 |

已发布的镜像会自动配置私有控制端点，不要为内部控制服务添加直接的宿主机端口映射。

HTTPS 模式只有在两个证书文件都可读时才启用严格 RTMPS。HTTPS 模式显式设置 `STREAM_INGEST_BASE` 时必须提供证书；否则可以关闭 RTMP。本机 HTTP 模式在内部 1935 端口使用明文 RTMP。镜像 Compose 不发布 1935。

## 端口与存储

| 端点/路径 | 用途 | 对外开放 |
| --- | --- | --- |
| 容器 TCP 8080 | NGINX Web/API 网关 | 宿主机回环，前方应部署 HTTPS 代理。 |
| 配置的 UDP/TCP 8189 | WebRTC 媒体 | 参与客户端需要直接可达。 |
| 容器 TCP 1936 | 可选 RTMPS 推流 | 仅使用 TLS 原生推流时开放。 |
| `/data` | SQLite 数据库、账户状态、加密历史/附件、头像和房间图片、设置状态 | 持久应用卷。 |
| `/watch-data/watch-videos` | 临时观影派对原始视频 | 独立媒体卷，派对状态保存在内存，启动会删除孤立的派对文件。 |
| `/tls` | 可选 RTMPS 证书链和私钥 | 只读绑定挂载，不属于应用数据。 |

除配置的数据卷和 `/tmp` tmpfs 外，文件系统只读。日志使用 Docker `local` 驱动，最多保留三个 20 MiB 文件。单镜像内存限制为 3072 MiB，进程数为 512，CPU 限制见上表。应通过审核后的 Compose 覆盖配置调整资源策略，而不是修改正在运行的容器。

## 应用限制

以下限制目前是应用代码中的常量，不是环境变量设置，也不构成性能保证。应用的存储计数与 SQLite 文件大小、备份大小和第三方进程内存不同。即使主机还有可用磁盘空间，达到应用上限仍可能拒绝新写入。

| 项目 | 当前限制与范围 |
| --- | --- |
| 普通房间 | 每实例 200 个，每账户最多拥有 32 个。房间创建计数不含私聊和临时房间。 |
| 房间成员 | 每房间 80 条成员记录，包括创建者和待加入记录，不代表 80 个同时在线的观看者。 |
| 持久聊天附件 | 每条消息最多 4 个附件，每附件明文最多 12 MiB（服务器额外允许 28 字节加密开销）。保存的加密附件总量为每实例 2 GiB、每上传账户 250 MiB。 |
| 持久聊天历史 | 普通频道与私聊的持久历史：每实例 300,000 条、每发送者 50,000 条；序列化加密消息封套另有每实例 256 MiB、每发送者 32 MiB 的字节上限。这不是明文字符数或整个数据库文件大小限制。 |
| 头像/房间图片 | JPEG、PNG 或 WebP 上传最多 8 MiB，图片解码器另限制 1600 万像素。 |
| 准备中/活跃屏幕直播 | 每实例 8 个，每账户只能有一个准备中或活跃直播。 |
| 已确认语音参与者 | 每直播频道 16 个，每实例 64 个；待加入和协商连接另有上限。 |
| 观影视频上传 | 每个 MP4/WebM 文件最多 256 MiB；本地视频预留存储每实例最多 512 MiB，包括队列中的上传。上传分块为 4 MiB，3 分钟没有进度会过期，总上传期限最长 20 分钟。 |
| 观影派对与队列 | 每实例最多 8 个活跃频道派对；每派对除当前视频外，最多另有 16 个后续项目。 |
| 临时房间 | 每实例 24 个，每所有者 1 个；草稿 5 分钟过期，房间最多持续 12 小时，媒体来源不活跃时可能提前结束。 |
| 临时直播聊天 | 每个临时房间聊天仅在内存保存最近 64 条密文消息，不属于永久历史。 |
