# 故障排查

[English](../troubleshooting.md) · [Deutsch](../de/troubleshooting.md) · [简体中文](troubleshooting.md) · [文档](README.md)

从症状出发，按相应链接处理。以下命令针对推荐的单容器部署，在仓库根目录执行，并使用与安装时相同的环境文件和 Compose 项目。

## 收集少量诊断信息

```sh
docker compose --env-file .env --project-directory . -f deploy/compose.image.yaml ps
docker compose --env-file .env --project-directory . -f deploy/compose.image.yaml logs --tail=100 rooms
```

若安装时没有使用 `.env`，请省略 `--env-file .env`。日志可能包含敏感信息，分享前请检查。

## 安装与启动

| 症状 | 检查和后续操作 |
| --- | --- |
| 无权拉取镜像 | 官方镜像可公开拉取。检查 `ROOMS_IMAGE` 的名称和标签、网络连接以及镜像仓库的可用性。如果 Docker 保存了失效的 GHCR 登录信息，请退出后重试。见[部署](self-hosting.md)。 |
| 容器因 Landlock 错误退出 | 镜像需要 Linux Landlock ABI 3 或更新版本，以及允许相关调用的 seccomp 配置。检查实际主机或虚拟机内核和容器运行时。应使用兼容环境，不要为隐藏错误而整体关闭隔离。 |
| 无权访问 `/data`、`/watch-data` 或证书 | 镜像以 uid/gid 1000 运行。检查卷所有者和该用户的读取权限。保持密钥权限严格，不要把数据改成所有人可写。见[维护](operations.md)。 |
| RTMPS 证书错误 | 公共 HTTPS 实例配置推流入口后，`/tls/fullchain.pem` 和 `/tls/privkey.pem` 必须同时存在且可读。检查绑定目录和完整证书链。仅浏览器屏幕分享本身不需要公共 RTMPS 入口。 |
| 远程无法打开网页 | 默认 Web 端口只绑定回环地址。使用已配置的 HTTPS 反向代理，或通过 SSH 隧道进行管理和本地测试。内部健康检查不是公共状态页面。 |
| 设置密钥被拒绝或初始化已关闭 | 确认密钥来自该实例的数据卷。所有者账户创建后，初始化会有意关闭。应使用所有者恢复流程，不要删除数据库。 |

参阅[部署](self-hosting.md)与[管理](administration.md)。

## 账户与加密历史记录

| 症状 | 检查和后续操作 |
| --- | --- |
| 更改域名或端口后无法登录 | 标准 origin 参与客户端凭据派生。核对访问地址及 `PUBLIC_ORIGIN`。不要先反复更换地址或重置账户。见[安全](security.md)。 |
| 操作提示来源错误 | 检查 HTTPS 协议、主机名、端口、反向代理 Host 头和 `PUBLIC_ORIGIN`。官方客户端与服务器必须使用相同 origin。 |
| 身份验证器代码被拒绝 | 检查设备与服务器时间同步，使用当前六位代码。已经使用的代码可能被拒绝。如适用，使用尚未使用的恢复码；所有者控制台恢复另有说明。 |
| 已登录但聊天锁定 | 在“解锁聊天”中输入保护账户身份的密码。恢复登录权限不会解密已遗忘的聊天密钥。 |
| 新成员看不到旧历史 | 请让有权限的成员打开并解锁浏览器，以便分享旧密钥。历史记录可能要等符合条件的密钥持有者重新上线。 |
| 无法读取临时房间中的旧消息 | 使用保留原本本地密钥的同一浏览器配置，并确认房间访问仍有效。清理存储、更换配置、密钥到期或房间结束可能使消息不可读。 |
| 桌面保持登录不可用 | 检查操作系统凭据存储是否运行并解锁。仍可手动登录。Linux 会有意拒绝固定密钥后备存储。 |

不要将清空浏览器数据或删除卷作为通用修复步骤，它们可能包含恢复所需的数据和密钥。

## 语音、分享与播放

| 症状 | 检查和后续操作 |
| --- | --- |
| 没有屏幕/窗口选择器或没有来源 | 检查浏览器和系统权限，以及与当前 GNOME/KDE 会话匹配的 ScreenCast portal。Wayland 需要 PipeWire 和可工作的 portal 后端。见[桌面](desktop.md)。 |
| Linux 客户端因沙盒警告拒绝启动 | 移除旧启动器中禁用沙盒的参数，使用发行版支持的非特权用户命名空间策略。Rooms 要求 Chromium 沙盒启用。 |
| 黑屏或采集引擎不可用 | 改用“Standard”、重新选择来源，并检查驱动与 portal。“Rooms Capture”是实验功能，不保证在所有硬件上更快。 |
| 应用音频列表为空 | 先让目标应用播放声音，再打开音频选择器。Linux 应检查 PipeWire 工具；Windows 应用音频需要受支持的系统版本。 |
| 应用或输出关闭后声音消失 | 重新开始直播并选择可用应用或输出。系统音频包含该输出上的其他声音。 |
| 语音或直接播放无法连接 | 检查公布的 `VOICE_ICE_HOST`、相同的 TCP/UDP 端口、NAT/防火墙连通性和 TLS。只代理网页不会让媒体端口自动可达。 |
| 画面延迟或速率跳动 | HLS 使用缓冲并可能分批下载。可用时尝试直接播放。统计含义见[直播指南](streaming.md)。 |
| 某项指标显示短横线 | 当前传输方式或采集后端可能无法提供该指标。原生 RTMP/HLS 不提供全部 WebRTC 统计。短横线表示不可用，不代表零丢包。 |
| YouTube 暂停或无法播放 | 最后一个观看者关闭或隐藏播放器时会暂停。此外检查视频是否允许嵌入、浏览器自动播放规则，以及 YouTube 是否可达。 |
| 视频上传被拒绝 | 检查 MP4/WebM 格式、256 MiB 限制和反向代理对 4 MiB 上传分块的支持。聊天附件与房间图片采用不同限制。 |

## 扩展与桌面链接

扩展和客户端必须使用完全相同的 Rooms origin。先启动桌面应用并确认实例。Linux 上应从准备长期存放的位置运行有执行权限的 AppImage，以便注册链接处理程序。

如果旧应用处理 `zelotez-rooms:`，请在系统链接设置中选择当前 Rooms 应用。扩展仍可选择“在浏览器中继续”。Firefox 临时扩展需在浏览器重启后重新加载。见[扩展指南](browser-extension.md)。

桌面更新检查为可选功能，查询官方 GitHub Releases。检查失败时，核对网络、GitHub 服务和请求频率限制，再手动打开[发行页面](https://github.com/ZeloteZ/ZeloteZ-Rooms/releases/latest)。应分别检查桌面版本和服务器版本。

## 报告可重现的缺陷

请提供：

- 执行了什么、预期结果，以及准确的可见错误。
- Rooms 服务器镜像标签/源码版本、相关桌面版本，以及使用浏览器还是桌面应用。
- 与故障有关的操作系统/桌面会话、浏览器版本、采集引擎和播放模式。
- 最少的重现步骤，以及故障前后经过脱敏的日志。
- 如有意义，说明使用“Standard”或其他受支持浏览器时是否也出现问题。

发布之前，删除 Cookie、令牌、完整访客/邀请/恢复链接、身份验证器二维码和密钥、私钥、私人聊天内容与无关地址。漏洞应通过[私密安全渠道](security.md#报告安全问题)报告。
